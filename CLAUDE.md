# QuizFlow Test (проходження тестів студентами) — правила для роботи з кодом

Частина сервісу QuizFlow на піддомені **test.quizflow.space**. Весь сайт розділений на чотири репозиторії:

| Піддомен | Репозиторій | Що там |
|---|---|---|
| app.quizflow.space | `quizflow-app` | панель викладача, вхід, сторінки ведучого гри |
| admin.quizflow.space | `quizflow-admin` | адмін-панель |
| play.quizflow.space | `quizflow-play` | гра наживо для учнів |
| test.quizflow.space | `quizflow-test` | проходження тестів студентами |

Цей репозиторій: Проходження тесту студентом за посиланням (іспит, контрольна; НЕ гра): одна сторінка `index.html` (`/?link=…&t=…` — тест за посиланням викладача, `/?testId=…&preview=1&t=…` — попередній перегляд із конструктора).

## Дизайн
- **Жодних емодзі в інтерфейсі.** Іконки — лише inline SVG (stroke, `currentColor`), позначки — текстом або CSS (крапка, смужка). Емодзі в контенті, який пишуть люди (назви тестів, тексти новин з адмінки тощо), не чіпаємо — правило лише про інтерфейс.
- **Жодних стандартних дропдаунів** (`<select>`, `<datalist>`, `<input type="date">`). Для вибору — власні компоненти (`qfDrop` у `quizflow-app/shared/features.js`, `ad-sel` в адмінці), для кількох варіантів — кнопки-чипи чи таби.
- Шрифти: Manrope (текст) і Geist Mono (цифри). Мова інтерфейсу — українська.

## Інфраструктура
- Сайт — статичний, GitHub Pages (Settings → Pages → Source: GitHub Actions; домен test.quizflow.space). Firebase — лише Realtime Database і Auth; платних Cloud Functions не використовуємо. Конфіг Firebase — один проєкт на всі частини.
- **Вхід Firebase не ділиться між піддоменами** (браузер зберігає його окремо для кожного). Тому вхід викладача — лише в `app`, вхід адміна — лише в `admin`; учням (`play`, `test`) вхід не потрібен.
- Правила бази, Cloudflare Worker пошти, `docs/` і генератори іконок та прев'ю лишаються в старому репозиторії `quizflow` (інфраструктура). Після змін правил їх треба вручну опублікувати в консолі Firebase.
- Після змін у `shared/*.js|css` піднімати `?v=` у всіх HTML цього репозиторію, де файл підключено.
- Іконки — `assets/icons/test/` і `/favicon.ico`. Це талісман (зелений паросток): генерується тут з `assets/icons/test/mascot.webp` командою `cd tests && npm run icons:mascot` (нове зображення: замінити файл, виконати скрипт, підняти `?v=` у посиланнях на іконки). Логотип у верхній смужці тесту — `assets/icons/test/sprout.webp`.
- Прев'ю посилань (Open Graph) — метатеги в `<head>` і `assets/og/test.jpg`; генеруються в `quizflow` (`npm run og`).

## Спільні файли (копії між репозиторіями)
Сайт — без збірки, тому спільні файли скопійовані. Змінили один — перенесіть у всі копії й підніміть `?v=`.

- `shared/qorder.js, ai-usage.js, caps.js, notices.js` — копії з `quizflow-app/shared/`: змінюйте там і переносіть сюди

## Піддомени: зв'язки з іншими частинами
Між частинами — лише абсолютні адреси (відносні шляхи між піддоменами не працюють):

- Окремих зв'язків немає: сторінка читає тест із бази за `link` і `t`.

## Процес
- Кожну завершену зміну — одразу комітити, пушити, відкривати PR у `main` і, щойно перевірки на GitHub зелені, зливати його в `main` без окремого підтвердження.
- Тести: `cd tests && npm ci && npx playwright test` (Firebase підмінено моком, справжня база не потрібна). Нова сторінка → додати в `tests/e2e/smoke.spec.mjs`.
- Текст, який вводять студенти чи інші користувачі, завжди екранувати (`esc`) перед вставкою в HTML.
